# TutorFlow AI / SE-MAS

Мультиагентный учебный прототип для задач по математике **5–9 классов**. Использует **LangGraph** для маршрутизации и выполнения агентов, локальные LLM через **Ollama**, **SymPy** для отдельных математических операций, **SQLite** для хранения истории и профилей, **FastAPI** для внешних запросов и **Arize Phoenix / OpenTelemetry** для трассировки (при включении интеграции).

## 1. Что умеет система

Входящий запрос проходит через `coordinator → student_profile`, затем по содержанию выбирается одна из веток:

| Запрос | Ветка графа |
| --- | --- |
| Решение математической задачи | `solver_agent → validator → save_db` |
| Проверка решения ученика | `solution_checker → validator → save_db` |
| Генерация упражнений / плана занятия / адаптация / уточнение | `generator → math_sandbox → validator → save_db` |
| Обработка небезопасных инструкций | `safety_node → save_db` |

Маршрутизация определяет тип запроса **по тексту**, а не по переданному клиентом `task_type`. Специализированные режимы `personalize`, `multi_step`, `clarify` не являются тремя отдельными агентами — они используют генератор с разными инструкциями.

## 2. Требования

- Windows 10/11 и PowerShell (примеры ниже для Windows).
- Python с виртуальным окружением `.venv` (проверялось пользователем на Python 3.13; CI использует 3.11).
- Установленный и запущенный **Ollama**; доступ к `http://127.0.0.1:11434`.
- Память и дисковое пространство для локальных моделей. Первый вызов LLM может занимать заметное время.

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если окружение уже создано, повторно создавать его не нужно; достаточно активировать.

## 3. Подготовка LLM

В отдельном терминале запустите Ollama, если она ещё не запущена:

```powershell
ollama serve
```

В терминале проекта скачайте используемые рабочим графом модели:

```powershell
ollama pull qwen2.5:3b
ollama pull llama3.2:3b
ollama list
```

В коде генератор использует `qwen2.5:3b`, решатель — `llama3.2:3b`; валидатор должен использовать **другое семейство**, чем соответствующий исполнитель. Переопределение при необходимости: `$env:TUTORFLOW_VALIDATOR_MODEL = "qwen2.5:3b"` (для ветки, где исполнитель — Llama). Не назначайте модель того же семейства.

## 4. Запуск API

Активируйте `.venv` и из корня репозитория запустите:

```powershell
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

Откройте документацию API в браузере: **http://127.0.0.1:8000/docs**. Состояние API: **http://127.0.0.1:8000/health**.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидаемый ответ: `status = ok`, `service = TutorFlow AI`. Это подтверждает запуск API, но **не доступность Ollama** и не качество генерации.

### 4.1 Универсальный маршрут: `/api/v1/agent`

Метод `POST`. Поддерживаемые поля входного JSON по контракту `AgentRequest`:

| Поле | Тип | Обязательность | Назначение |
| --- | --- | --- | --- |
| `user_prompt` | `string` (2–4000 символов) | **Да** | Текст запроса |
| `grade` | `integer` (5–9) | Нет | Класс ученика |
| `student_level` | `string` (до 100 символов) | Нет | Уровень знаний |
| `weak_topics` | `string` (до 500 символов) | Нет | Слабые темы для персонализации |

**Важное ограничение:** публичный endpoint в проверенной версии **не объявляет поля `task_type`, `student_name` или `session_id`**. Не пытайтесь ими управлять маршрутом и не рассчитывайте, что переданный `session_id` сохранит историю: Pydantic может проигнорировать лишние поля. Внутренний граф поддерживает сессии, но внешний контракт намеренно ограничен до появления контроля доступа.

Пример 1 — решить уравнение:

```powershell
$body = @{
  user_prompt = "Реши уравнение 2x + 5 = 15"
  grade = 7
} | ConvertTo-Json -Compress

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/agent" `
  -Method Post -ContentType "application/json; charset=utf-8" -Body $body
```

Пример 2 — упражнения с учётом слабой темы:

```powershell
$body = @{
  user_prompt = "Составь 3 упражнения по дробям для ученика 6 класса с разбором"
  grade = 6
  student_level = "начальный"
  weak_topics = "приведение дробей к общему знаменателю"
} | ConvertTo-Json -Compress

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/agent" `
  -Method Post -ContentType "application/json; charset=utf-8" -Body $body
```

Формат ответа `/api/v1/agent`:

```json
{
  "trace_id": "...",
  "task_type": "solve_math",
  "validation_status": "APPROVED",
  "final_output": "...",
  "is_correct": null,
  "latency_sec": 0.0
}
```

Значения здесь иллюстрируют **структуру**, а не гарантированный вердикт или задержку. `task_type` возвращается **по результатам классификации текста**; `is_correct=null` допустим для задач, где не проверяется ответ ученика.

### 4.2 Проверка ответа ученика: `/api/v1/check-solution`

Метод `POST`, одно обязательное поле `prompt` (от 5 символов). Формулируйте условие, решение и ответ достаточно явно:

```powershell
$body = @{
  prompt = "Проверь решение задачи 2*x + 4 = 10. Ученик ответил x = 3. Верно ли это?"
} | ConvertTo-Json -Compress

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/check-solution" `
  -Method Post -ContentType "application/json; charset=utf-8" -Body $body
```

Ответ содержит `is_correct` (`true` / `false` / `null`), `math_solution`, `feedback`, `latency_sec`. `null` означает отсутствие надёжно установленного булева вердикта. При неопознанном типе запроса возможен HTTP `422`.

## 5. Phoenix: трассы агентов (опционально)

В ветке, где добавлен модуль `src/observability/phoenix_tracing.py` и его вызов в `src/api/main.py`, трассировка включается **переменной окружения**. Phoenix **не нужен**, чтобы API работал в обычном режиме.

Если библиотеки Phoenix отсутствуют, установите их отдельно (в исходном `requirements.txt` из аудированной версии они **не указаны**):

```powershell
python -m pip install arize-phoenix arize-phoenix-otel openinference-instrumentation-langchain
```

В терминале №1:

```powershell
phoenix serve
```

Интерфейс: **http://127.0.0.1:6006**.

В терминале №2 с активированной `.venv`:

```powershell
$env:PHOENIX_ENABLED = "1"
$env:PHOENIX_ENDPOINT = "http://127.0.0.1:6006/v1/traces"
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

Теперь запросы отправляются **как обычно через `/api/v1/agent`** (см. §4). В Phoenix откройте проект `TutorFlow-AI` → Traces. Должны появляться вложенные span, если автоматическое инструментирование активировано. Отдельные тестовые `phoenix_test.py`, `phoenix_graph_test.py` и `phoenix_agents_test.py` **для работы системы не нужны**.

**Подтверждено экспериментально:** Phoenix получал тестовые OpenTelemetry-трассы и показывал вложенные шаги реального LangGraph с заглушками вместо LLM. **Не подтверждено на момент подготовки README:** поступление трасс после настоящего LLM-запроса через запущенный процесс FastAPI. Не выдавайте тест на заглушках за полноценную e2e-трассировку.

Встроенное локальное логирование выполняется независимо от Phoenix: `.runtime/events.jsonl` содержит обезличенные сведения о запросах, узлах, задержках и вызовах моделей. Если у вас установлен `scripts/observability_report.py`, можно построить сводку командой:

```powershell
python scripts/observability_report.py --md-out results/observability_report.md --json-out results/observability_report.json
```

**Быстрые тесты без полного LLM-прогона:**

```powershell

```

**Аудит маршрутизации 42 кейсов (без Ollama):**

```powershell

```

**Реальный запуск первых трёх сценариев датасета с локальными LLM (может быть медленным):**

```powershell
python scripts/run_graph_dataset.py --limit 3
```

Полный датасет:

```powershell
python scripts/run_graph_dataset.py
```

Ожидаемые пути: `benchmarks/dataset.jsonl`, результаты в `results/graph_dataset/`, маршрутный отчёт в `results/route_audit.csv`. **42/42 совпадений маршрута не означают 42 правильных математических ответа.** Содержательное качество требует эталонной проверки.

Последний локальный отчёт тестов: **36 passed, 1 deselected, 2 warnings**. Это результат конкретного запуска, а не гарантия на иной машине.

## 8. Критические ограничения до сдачи / развёртывания

1. **Изоляция исполнения.** `src/tools/sandbox.py` использует подпроцесс, ограничения ввода и тайм-аут. **Это не VM/MicroVM**, и среда не изолирована от файловой системы/сети учётной записи. Для строгого соответствия ТЗ требуется ОС-изоляция с лимитами ресурсов.
2. **Контроль доступа.** Нет аутентификации, авторизации, безопасной привязки ученика и защиты от доступа к чужим данным. Не публикуйте API в интернете; используйте только локальные тестовые данные.
3. **Верификация математической правильности.** LLM-валидатор из другого семейства полезен, но не является формальным доказательством; `APPROVED` может быть неверным. Нужны независимые эталонные проверки и негативные сценарии.
4. **E2E и observability.** Требуется подтверждение сквозной трассы настоящего API-запроса в Phoenix и метрик качества/ошибок. Тесты отдельных компонентов этого не заменяют.
5. **Память и RecSys.** История SQLite и загрузка профиля работают; автоматическое обновление слабых тем, защищённая идентификация пользователей и использование Two-Tower внутри публичного графа не подтверждены.

Дополнительные требования преподавателя (семь C4-представлений + sequence diagram, сравнение моделей/движков, обоснование фреймворка, skills, evals) описываются в общем отчёте и должны соответствовать **фактически реализованному** коду.

## 9. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `503`, граф не инициализирован | Запускайте через `uvicorn`, чтобы выполнялся FastAPI lifespan |
| Ошибка соединения с Ollama | Запущен ли `ollama serve`, есть ли модели в `ollama list` |
| `task_type=pedagogical` вместо ожидаемого | Убедитесь, что формулировка `user_prompt` явно указывает операцию, например «Реши уравнение...»; `task_type` не является полем публичного запроса |
| Phoenix пуст | Запущен ли `phoenix serve`, задано ли `PHOENIX_ENABLED=1` **до** старта API, указан ли HTTP endpoint `/v1/traces` |
| Ошибка sandbox timeout | Зафиксируйте нагрузку и время выполнения; не увеличивайте лимит произвольно без анализа безопасности |
| `pytest` обнаруживает временные `*_test.py` | Запускайте `python -m pytest tests -q -m "not slow"` и не храните одноразовые тестовые файлы в корне |
