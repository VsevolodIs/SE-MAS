# Итоговое сравнение LLM для TutorFlow AI (A03 / Evals)

## 1. Цель

Оценить локальные модели для задач обучения математике 5–9 классов по **качеству математических ответов**, полноте генерации и скорости, не смешивая эти три критерия. Исходные ответы сохранены после экспериментов 8 ноября 2026 года; повторный инференс для подготовки этой сводки не проводился.

## 2. Дизайн эксперимента

Три модели в Ollama: `llama3.2:3b`, `gemma3:4b`, `qwen3:4b`. Каждая обработала **42 сценария** из `benchmarks/dataset.jsonl` с параметрами `seed=42`, `temperature=0`, `num_predict=1024`, `think=false`; для Qwen дополнительно задано `qwen_no_think=true`. Использовалось одно локальное окружение Windows, Python 3.13.5. Средний TTFT определялся по первому непустому фрагменту content или thinking; TPS — по `eval_count / eval_duration` Ollama.

Для предметного сравнения отдельно проанализированы **10 сценариев `solve` и 7 сценариев `check_solution`** на каждую модель. Это не полная оценка всех 42 сценариев: качество уроков, персонализации, безопасности и генерации упражнений должно оцениваться другими рубриками. Наличие ответа и статус HTTP не означают математическую правильность.

## 3. Результаты

| Метрика | Llama3.2 3B | Gemma3 4B | Qwen3 4B |
|---|---:|---:|---:|
| Всего запросов | 42 | 42 | 42 |
| Завершено без обрезания | **42** | 40 | 22 |
| Обрезано | 0 | 2 | 20 |
| Completion rate | **100%** | 95,24% | 52,38% |
| Средний TTFT | **3,183 с** | 5,274 с | 5,690 с |
| Средний TPS | **13,373** | 11,392 | 5,617 |
| Среднее wall time | **22,308 с** | 32,686 с | 199,898 с |
| Правильные `solve` (экспертный просмотр) | 9/10 | 9/10 | **10/10** |
| Правильные `check_solution` | 3/7 (+1 частично) | 3/7 (+1 частично) | **7/7** |

Для `check_solution` частично правильный ответ **не** засчитан в 3/7: в учебном сервисе правильный результат с неверным объяснением может быть опасен с педагогической точки зрения.

## 4. Конкретные ошибки и ограничения

- `gemma3:4b`, TF-003: ответ 480 руб. вместо правильных 680 руб. после скидки 15% от 800 руб.
- `llama3.2:3b`, TF-009: ответ `x=3, y=4` вместо `x=4, y=3` при системе `x+y=7`, `x−y=1`.
- `llama3.2:3b`, TF-018: неверное определение дискриминанта — существенная ошибка для обучающего агента.
- `qwen3:4b`: 20 ответов остановлены с `done_reason=length` и `output_tokens=1024`. Следовательно, причиной **формального обрезания** является установленный предел генерации; это не доказывает низкое качество математических знаний Qwen.
- В части сохранённых ответов Qwen присутствует текст, похожий на рассуждения, внутри `answer`, хотя настройка `think=false`; это повышает стоимость генерации и риск потратить лимит до пользовательского ответа.

### Ограничения оценки

1. Доля правильных решений измерена на **10** заданиях `solve`, а доля правильных вердиктов — на **7** заданиях `check_solution` для каждой модели. Маленькая выборка не позволяет экстраполировать проценты на всю математику 5–9 классов.
2. Качество первых ответов трёх моделей **не является качеством мультиагентного TutorFlow AI**: специализированный граф, SymPy и валидатор могут изменить результаты в обе стороны.
3. Для строгого сравнения требуется фиксировать оборудование, объём памяти, квантизацию, прогрев, контекст и количество повторов. Здесь приведены результаты уже существующих запусков, а не независимая статистическая репликация.
4. `Qwen` на текущем устройстве слишком медленна для интерактивной работы, но нельзя утверждать, что она принципиально слабее в математике.
5. Оценка некоторых критериев выполнена экспертным просмотром сохранённых ответов; методика не равноценна автоматическому воспроизводимому тесту на большом наборе эталонов.

## 5. Вывод и выбор моделей

- **Координатор:** `llama3.2:3b` — кандидат по наименьшей задержке и наибольшей полноте ответов. Необходимо отдельно проверить качество маршрутизации.
- **Генерация и объяснение математических задач:** `qwen3:4b` показала лучший результат на коротких задачах, но в имеющемся локальном окружении имеет неприемлемо высокую задержку для большинства интерактивных сценариев. Для MVP можно использовать более быстрый генератор вместе с обязательной инструментальной проверкой, сохраняя Qwen как R&D baseline.
- **Валидатор:** выбирать LLM другого семейства относительно генератора и подтверждать её эффективность обнаружения ошибок; **одного факта различия семейств недостаточно**. Gemma остаётся кандидатом, но на этих семи примерах допустила ошибки.
- **Критические вычисления:** выполняются не на доверии к одной LLM, а через проверяемый математический tool и проверку шагов. Технические ошибки парсера должны давать статус «нужна дополнительная проверка», не автоматическое «ученик ошибся».

## 6. Интеграционный статус

В отдельном прогоне было обработано 42/42 API-запроса: 7 — через `solution_checker`, 4 — через `lesson_graph`, 31 — через `generic_llm_fallback`. Это подтверждает доступность API-пути, **но не полноценную интеграцию всех восьми типов задач в мультиагентный граф**. Финальный прогон нужно повторить после изменений backend от второго участника команды.
